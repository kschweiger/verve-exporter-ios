# Design Docs

Design docs describe how the repository should be changed technically and why.

Use this directory for:

- Architecture changes.
- Larger technical changes.
- Component boundaries and data flow.
- Trade-offs and options considered.
- Rollout and validation strategy.

Keep `docs/DECISIONS.md` compact. Link to a design doc when a decision needs more context than a short entry.
